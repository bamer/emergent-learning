# big-pickle Handler (Tier 2) Specification

**Replaces**: Opus Handler from original architecture
**Model**: opencode/big-pickle (local, zero-cost)
**Status**: ✅ IMPLEMENTATION COMPLETE
**Date**: 2026-01-28

---

## Overview

The big-pickle Handler is Tier 2 of the watcher system. It's invoked only when Tier 1 (watcher) detects issues.

The Handler's job: **Make decisions** and **take action** to resolve or escalate issues.

## Execution Flow

```
Tier 1 (Watcher) detects issue
            ↓
       Exit Code 1
            ↓
Tier 2 (Handler) invoked
            ↓
Read full context (blackboard.json, logs, etc.)
            ↓
Analyze with big-pickle
            ↓
Decide action:
  • RESTART agent
  • ABANDON task
  • ESCALATE to human
            ↓
Execute decision
            ↓
Update blackboard.json
            ↓
Log decision to decision.md
            ↓
Record to event_chronicle
            ↓
Exit (0=resolved, 1=escalated)
```

## Handler Invocation

From `run_with_bigpickle.py`:

```python
def run_handler_pass(escalation_reason: str) -> Tuple[str, bool]:
    """Run handler/CEO tier to make decisions."""
    
    # Generate handler prompt using watcher_loop.py
    output_handler_prompt(escalation_reason)
    
    # Send to big-pickle via CLI
    response = call_bigpickle(handler_prompt)
    
    return response, success
```

## Handler Prompt Structure

Generated by `watcher_loop.py::output_handler_prompt()`:

### Context Section
- Escalation details from Tier 1
- Full blackboard.json state
- Recent log entries
- Error contexts

### Analysis Tasks
1. **Gather Context**
   - Read .coordination/blackboard.json
   - Read .coordination/watcher-log.md
   - Check agent_*.md files

2. **Analyze Situation**
   - What went wrong?
   - Is it recoverable?
   - What's the root cause?

3. **Decide Action**
   Choose one:
   - **RESTART**: Agent stuck but task valid
   - **ABANDON**: Task is invalid/impossible  
   - **ESCALATE**: Need human decision

4. **Execute Decision**
   - Update blackboard.json (status field)
   - Write to .coordination/decision.md
   - Log to watcher-log.md

5. **Log and Exit**
   - Output summary block
   - Return appropriate exit code

## Decision Actions

### RESTART
**When**: Agent marked "active" but not updating (stale)

**Action**:
```python
# Update blackboard.json
bb["agents"]["agent-id"]["status"] = "restarting"
bb["agents"]["agent-id"]["last_seen"] = datetime.now().isoformat()

# Record to event_chronicle as 'handler_decision'
# with data: {"decision": "RESTART", "agent": "agent-id"}
```

**Outcome**: Watcher will detect restart and continue monitoring

### ABANDON
**When**: Task is invalid, impossible, or fundamentally broken

**Action**:
```python
# Update blackboard.json
bb["agents"]["agent-id"]["status"] = "abandoned"
bb["agents"]["agent-id"]["reason"] = "task impossible"

# Record to event_chronicle
# with data: {"decision": "ABANDON", "reason": "..."}
```

**Outcome**: Agent marked as abandoned, watcher continues

### ESCALATE
**When**: Situation requires human judgment

**Action**:
```python
# Create file in ceo-inbox/ for human review
Path("ceo-inbox/decision-TIMESTAMP.md").write_text(analysis)

# Record to event_chronicle
# with data: {"decision": "ESCALATE", "reason": "..."}

# Exit with code 1 to signal escalation
exit(1)
```

**Outcome**: Human reviews in ceo-inbox/, makes final decision

## Handler Event Recording

Handler records `handler_decision` events to `event_chronicle`:

```json
{
  "event_type": "handler_decision",
  "source": "watcher",
  "source_id": "bigpickle-handler",
  "status": "nominal|warning|critical",
  "summary": "Handler made decision: RESTART/ABANDON/ESCALATE",
  "data": {
    "tier": 2,
    "escalation_reason": "stale agents detected",
    "decision": "RESTART",
    "affected_agents": ["worker-1"],
    "outcome": "agent restarted successfully"
  }
}
```

## Handler Logging

Logs to `.coordination/decision.md`:

```markdown
## [2026-01-28T10:31:15] HANDLER DECISION

**Issue**: Agent worker-1 stale (no update for 150 seconds)

**Analysis**: 
- Agent marked as active
- Last heartbeat: 2026-01-28T10:30:45
- Current time: 2026-01-28T10:32:35
- Status: Definitely stale

**Root Cause**: Agent process may be hung or crashed

**Action**: RESTART
- Updated agent status to "restarting"
- Will be picked up by next watcher cycle

**Outcome**: Success - agent ready for restart
```

Also appends to `.coordination/watcher-log.md`:

```
2026-01-28T10:31:16.456789 | [TIER 2] Handler decision: RESTART
2026-01-28T10:31:17.567890 | Decision: Restarted stale agent worker-1
```

## Handler Capabilities

### File Operations
- ✅ Read: blackboard.json, *.md files in .coordination/
- ✅ Write: decision.md, watcher-log.md
- ✅ Update: blackboard.json (agent status)
- ✅ Create: ceo-inbox/*.md (for escalation)

### Analysis Tools
- ✅ Access full coordination state
- ✅ Parse agent logs
- ✅ Detect error patterns
- ✅ Understand task context

### Decision Scope
- ✅ Can restart agents
- ✅ Can abandon tasks
- ✅ Can escalate to human
- ✅ Can NOT spawn new agents (that's main Claude)
- ✅ Can NOT modify task definitions (read-only)

## Handler Exit Codes

| Code | Meaning | Next Step |
|------|---------|-----------|
| 0 | Resolved successfully | Watcher continues normally |
| 1 | Escalated to human | ceo-inbox/ has decision |
| 2 | Error occurred | Watcher logs error, retries |

## Model Configuration

Handler uses big-pickle via OpenCode CLI:

```bash
claude --print --model opencode/big-pickle << EOF
```

- Local model (no network calls)
- Instant response
- Full context available
- Zero API costs

## Integration Points

### Input from Tier 1
- Escalation reason/analysis
- Issue context
- Status from watcher_cycle event

### Output to System
- Updated blackboard.json
- decision.md file
- event_chronicle record
- watcher-log.md entry
- ceo-inbox/* (if escalating)

### Next Cycle
- Watcher checks if status changed
- If RESTART: agent will be retried
- If ABANDON: task marked done
- If ESCALATE: human makes decision

## Error Handling

If big-pickle call fails:

```python
if not success:
    # Record error to chronicle
    record_to_chronicle(
        event_type='handler_error',
        status='critical',
        summary=f'big-pickle failed: {error}'
    )
    # Return exit code 2 (error)
    return 2
```

Watcher will retry on next cycle.
